Flujos de crédito
Cuando un cliente tiene la condición de Crédito debe ir a validar el límite en SAP (véase 98. Interfaces ).
Cuando un cliente tiene la condición de Financiamiento puede elegir entre planes (véase 4. Tipos de Crédito (Financiamiento)) y valida el límite desde el SFA (véase 98. Interfaces ).
Las formas de pago de Crédito o Financiamiento se habilitan si el cliente tiene la condición marcada desde datos maestros; no depende del tipo de cliente sino del maestro.

Formas de pago dinámicas ✅
Módulos: 🛠️ Site admin | 📦 Inventario Web | 💵 POS
Se deben registrar múltiples formas de pago desde el site administrativo para crear, modificar, activar/desactivar formas de pago y que se muestren en el módulo de Punto de Venta.

Se puede ingresar un número de referencia opcional.

Cada forma de pago afecta al cierre de cajas y los retiros dinámicos son calculados automáticamente.

Se debe incluir en los cierres de caja trastienda en Inventario Web.

Incluir el menú (Empresa > Otras formas de pago) en las tablas de Permisos.

Las “otras formas de pago” se crean a nivel de empresa.

Cada forma de pago se puede activar/desactivar desde sucursal y caja, como se hace actualmente con las otras formas de pago.

Bloqueo de crédito ✅
Módulos: 🛠️ Site admin | 💵 POS
Estado para bloquear un cliente (similar al activo/inactivo). Esto se guarda asi en nube.

Validar el estado de bloqueo al facturar. No permitiría documentos de ningún tipo. Proformas si se permiten.

Además del estado del cliente en la nube, un cliente se puede bloquear desde el punto de venta, y solo local (no se sincroniza el estado hacia arriba).

Cada vez que se bloquea o desbloquea se guarda en bitácora.

Se debe guardar una bitácora y subirla al server por cada cambio de bloqueo/desbloqueo.

Criterios de aceptación
Si el cliente está bloqueado, no permite transacciones de venta (contado, crédito, regalías, preventas, planes de financiamiento).

Si permite crear devoluciones, movimientos de caja y proformas.

El bloqueo es local. Si se bloquea en una caja nunca debe propagarse a la nube (o sea, no se propaga a otras cajas o sucursales)

Cambiar el estado de bloqueo desde el servidor si propaga el cambio a las sucursales. O sea, sobrescribe el estado de bloqueo que exista en una sucursal.

El estado de bloqueo local se va a actualizar con el valor de la nube si ese cliente se actualizó posteriormente a la última fecha de sincronización.

Si el cliente se bloquea local, pero no en la nube, el estado seguirá siendo bloqueado hasta que se desbloquee localmente o se actualice cualquier valor.

El botón de "bloqueado" en el mantenimiento cambia el texto si está actualmente bloqueado o desbloqueado.

Se muestran los clientes bloqueados localmente si están desbloqueados en línea. Muestra la sucursal y caja donde sigue bloqueado.



Depósitos automáticos
Módulos: 💵 POS
Crear un depósito automático al generar un retiro.

Se solicita un número de depósito y banco.

Parámetro por caja para configurar si el depósito se debe solicitar durante el retiro.

Criterios de aceptación
Si el parámetro de la caja para solicitar el depósito está activo, se muestra la pantalla siempre durante el retiro.

El depósito va en la misma transacción del retiro; o sea, si falla el depósito, no se concluye el retiro.

Es requerido llenar la información del depósito.

La pantalla de depósito solo se muestra si hubo retiro de efectivo, cheque o moneda extranjera.

El retiro se hace automáticamente con los montos de efectivo + cheque + moneda extranjera, todo en colones.
