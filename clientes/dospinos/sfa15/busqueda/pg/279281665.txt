PROPUESTA DE SOLUCIÓN
Servicios de Informática Lexington S.A. ofrece a Cooperativa De Productores De Leche Dos Pinos, R.L. la presente propuesta de solución con el objetivo de diseñar, desarrollar e implementar las integraciones necesarias entre la plataforma LDCOM y los sistemas centrales Dos Pinos, abarcando los procesos transaccionales de ventas, inventarios, financiamiento y operaciones de caja.
Esta oferta constituye la segunda fase del proyecto de integración de interfaces, complementando la oferta CO-696-0021 (Integración Datos Maestros) que abordó la sincronización de catálogos y datos maestros. En esta fase se desarrollan los 28 flujos transaccionales que soportarán la operación diaria de ventas, despacho, facturación, gestión de inventarios y autorización de créditos entre ambas plataformas.
SITUACIÓN ACTUAL 
Actualmente no existe un mecanismo centralizado y parametrizable que permita la comunicación entre sistemas Dos Pinos y LDCOM, gestionar frecuencias de sincronización de forma independiente o monitorear el flujo de datos en tiempo real de los flujos transaccionales de ventas, financiamientos e inventarios.
ALCANCE DE LA PROPUESTA 
La integración comprende 26 interfaces agrupadas en 15 flujos de datos que se comunican a través de 16 endpoints (8 Endpoints en el API LDCOM y 8 endpoints en el API Dos Pinos). 
Todos los flujos pasan por el componente de integración API LDCOM, el cual gestiona el envío y recepción de datos, reintentos automáticos y reporte de eventos al Monitor Integral 360.

Paso a paso del flujo FL-01 Documentos de ventas y devoluciones 
(Envío consolidado de documentos)
Paso 1: El cajero realiza el cierre de caja en LDCOM.

Paso 2: El API LDCOM envía, de forma consolidada, todos los documentos de venta (facturas, devoluciones) al API Dos Pinos.

Paso 3: Dos Pinos recibe los documentos y devuelve la confirmación de recepción.

Paso 4: API LDCOM registra el resultado del evento y lo notifica al Monitor 360.

Paso a paso del flujo FL-01 Documentos de ventas y devoluciones 
(Ventas y devoluciones de crédito para distribuidores)
Paso 1: El cajero realiza la venta o devolución de crédito (Distribuidores) en el punto de venta LDCOM.

Paso 2: El API LDCOM envía, en tiempo real, el documento al API Dos Pinos.

Paso 3: Dos Pinos recibe el documento y devuelve la confirmación de recepción.

Paso 4: API LDCOM registra el resultado del evento y lo notifica al Monitor 360.

Cambio 3. Autenticación M2M mediante Azure Active Directory
Descripción: La autenticación entre el API de Dos Pinos y el API LDCOM se realizará mediante el protocolo OAuth 2.0 con el flujo Client Credentials, utilizando Azure Active Directory (Azure AD) como proveedor de identidad. Este mecanismo es estándar para integraciones M2M (machine-to-machine) y elimina la necesidad de gestionar credenciales personalizadas dentro de LDCOM.
Funcionamiento:
Dos Pinos registra una aplicación en su propio tenant de Azure AD (App Registration).

Dos Pinos utiliza el client_id y client_secret de esa App Registration para solicitar un token de acceso al endpoint de OAuth de Azure AD.

El token obtenido (JWT firmado por Azure) se incluye en cada request al API LDCOM como Authorization: Bearer <token>.

El API LDCOM valida la firma del token contra las claves públicas del tenant de Dos Pinos. No genera ni firma tokens propios.

Desarrollo requerido en LDCOM:
Implementar validación de tokens JWT en el API LDCOM, verificando firma, expiración y claims relevantes (aud, iss, appid).

Configurar en LDCOM los datos del tenant de Dos Pinos necesarios para la validación (ver Supuestos).

Crear una App Registration propia en Azure AD de Logical Data para representar al API LDCOM como recurso protegido (resource app), necesaria para que los tokens emitidos tengan el audience correcto.

SUPUESTOS Y RESTRICCIONES
Alcance: 
Esta oferta incluye en el alcance únicamente las interfaces especificadas en el presente documento.

Esta oferta no contempla cambios en el desarrollo distintos a los expresamente indicados. Cualquier modificación al alcance aquí descrito deberá ser sometida a un nuevo análisis y a la correspondiente evaluación de impacto para determinar las implicaciones de su inclusión. Bajo esta premisa, quedamos atentos a su validación, a fin de confirmar que el alcance definido refleja adecuadamente las expectativas actuales y poder avanzar con una ejecución debidamente alineada. 


Dependencias:
El inicio del desarrollo del alcance de esta oferta requiere de la aprobación y desarrollo previo de la oferta CO-696-0021 Integración de Interfaces para Datos Maestros. Esto debido a que dicha oferta incluye la infraestructura base del API LDCOM necesario para los flujos e integraciones transaccionales. 


Canales de comunicación: 
Es de suma importancia que exista un canal de comunicación ágil entre Dos Pino, LD y otros proveedores, con el objetivo que el equipo de línea de producción pueda comunicarse en directo con los equipos y estos respondan de forma ágil. 

Si durante el proceso de línea de producción (desarrollo o aseguramiento de la calidad), existe una incidencia que no permita continuar con el proceso ya que es dependiente de la respuesta del proveedor o Dos Pinos para continuar, si la misma no se recibe en un periodo de 32 horas laborales, el proyecto se colocará en estado detenido hasta tener respuesta y volver a retomar el proceso de línea de producción. 


Sesiones para certificación de integración: 
Se deberán coordinar sesiones de certificación para validar el flujo completo de sincronización de datos maestros.


Reportes: 
Esta oferta no incluye en el alcance la creación de reportes en LDCOM.


Autenticación:
Para el acceso de los sistemas de Dos Pinos al API LDCOM, se asumen los siguientes puntos:
Dos Pinos gestionará su propia App Registration en su tenant de Azure AD. LDCOM no administra ni almacena credenciales de Dos Pinos.

Dos Pinos proveerá el endpoint de claves públicas (JWKS URI) de su tenant, necesario para que LDCOM valide las firmas de los tokens emitidos.

Logical Data creará una App Registration en su propio tenant de Azure AD para representar al API LDCOM como recurso protegido. Dos Pinos deberá autorizar el acceso a este recurso desde su App Registration.

La integración opera en modalidad cross-tenant: el tenant de Dos Pinos emite los tokens y el tenant de Logical Data (LDCOM) los valida. Esto requiere que ambas partes coordinen los identificadores de aplicación (client_id, Application ID URI) antes del inicio del desarrollo.

LDCOM únicamente valida tokens; no firma, no emite ni almacena tokens de acceso.

Si durante el desarrollo Dos Pinos define un mecanismo de autenticación distinto al aquí descrito, esto quedará sujeto a revisión de alcance de la presente oferta.


Infraestructura
Se asume en esta oferta que todas las integraciones hacia Dos Pinos van a un API con el mismo dominio y autenticado de la misma forma (o sea, cada endpoint o interface comparte la misma URL base. Ej., https://api.dospinos.com/v1/…). Por tanto la configuración de la URL y el API Key es única para todas las interfaces. Si durante el desarrollo se define algo distinto, podría quedar sujeto a cambios de alcance en esta oferta.

Se asume en esta oferta que existirá un ambiente de pruebas estable para integraciones, además del ambiente de producción. Dos Pinos brindará la documentación, llaves y accesos para conectarnos a cada ambiente.

La documentación de las interfaces se realizará mediante herramientas por definir, como Postman.


Desarrollo del API
Los flujos que requieren integraciones en LDCOM de endpoints del API Dos Pinos, se van a desarrollar hasta que Dos Pinos haya compartido los ambientes y la documentación de cada endpoint. Si durante esta fase, Dos Pinos desarrolla algo distinto a lo acordado, podría quedar sujeto a cambios de alcance en esta oferta.

Los sistemas de Dos Pinos deberán consumir los endpoints del API LDCOM respetando estrictamente los contratos y validaciones definidas.

Se requiere conectividad en línea entre Dos Pinos y LDCOM para el consumo de los endpoints que operan en tiempo real o bajo demanda.

Todos los endpoints del API LDCOM estarán sujetos a políticas de seguridad, autenticación y autorización definidas por LDCOM.

Los endpoints contarán con políticas parametrizables de:
Notificación de eventos exitosos y fallidos al Monitor Integral 360.


Los eventos procesados por los endpoints serán registrados y auditados en el Monitor Integral 360.

Los datos requeridos por los endpoints pueden variar conforme se incorporen nuevos alcances funcionales, siempre bajo análisis y validación de impacto.

Para endpoints transaccionales, los datos recibidos deberán cumplir con todas las validaciones funcionales y de negocio establecidas en LDCOM (por ejemplo: existencia, estado, integridad de la información).

Cualquier cambio significativo en los contratos, validaciones o comportamiento de los endpoints podrá estar sujeto a una revisión de alcance de la presente oferta.

La documentación técnica correspondiente.

Cantidad máxima de reintentos.

Código de interfaz para auditoría.

Política de notificación de eventos al Monitor Integral 360.


Se requiere conectividad en línea con el API Dos Pinos para el envío y recepción de información según la periodicidad definida en cada flujo.

En caso de indisponibilidad temporal del API Dos Pinos:
LDCOM aplicará las políticas de reintentos configuradas por interfaz.

Los eventos pendientes serán reenviados una vez restablecida la conectividad.


Todos los eventos enviados al API Dos Pinos serán monitoreados y registrados en el Monitor Integral 360, tanto en escenarios exitosos como fallidos según la configuración.

Únicamente los flujos e interfaces explícitamente indicados en el alcance de esta oferta estarán habilitados para integrarse con dichos endpoints.

Los cambios en los contratos, comportamiento o disponibilidad de los endpoints del API Dos Pinos que difieran de lo acordado podrán requerir una revisión de alcance de la presente oferta.


Flujo de datos
Por razones de integridad de datos, los flujos de sincronización solo insertan o actualizan registros; No se pueden eliminar desde datos maestros. En LDCOM si se pueden eliminar manualmente los datos que no tengan transacciones relacionadas.

Se asume en esta oferta que el API de Dos Pinos brindará parámetros en los endpoints de catálogos grandes (como clientes, proveedores o artículos) para filtrar por fecha de modificación y paginación. Si los endpoints de Dos Pinos no pueden ofrecer estos parámetros la sincronización podría ser más lenta y saturar más los servicios. Si esto no es posible a la hora de integrarse, queda sujeto a cambios en el alcance de esta oferta.

Los contratos (conocidos como “schemas”) de cada endpoint de LDCOM y de Dos Pinos aún no se han definido e irán detallándose en el transcurso del proyecto. La cantidad de campos o endpoints podría variar. Sin embargo, si durante esta fase se cambia el desarrollo de forma que involucre un aumento significativo en el alcance, como cambios en la parametrización, creación de catálogos nuevos, o cambios significativos en los “contratos de cada endpoint” una vez se esté implementando, podría quedar sujeto a cambios en esta oferta.
